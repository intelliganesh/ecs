# What Retirement Builder actually does

Investigation date: 18 November 2026. This guide describes the current working tree, including its existing uncommitted changes. No application code or database data was changed for this investigation. Evidence labels and totals are defined in [README](README.md).

## Explain it in one minute

**Retirement Builder is a configurable report and export job builder.** A user defines the output file name, separator, schedule, output columns, filters, sorting, and email recipients. Finish saves the job. Run generates delimited files from the saved source, optionally saves the generated rows to a results table, and can send matching files by email. These are separate actions: saving a job does not run it. The implementation has **no retirement age, investment growth, pension projection, contribution-rate input, or savings target formula** in this feature. Its payroll procedure counts joined payroll records and totals net salary. ## A simple example using fake data

Suppose an operations user wants a monthly payroll summary for **Example Manufacturing**, a fictional company with ID **101**. Two payroll rows for November have net salaries 2,500.25 and 3,000.50. The current payroll source returns an employee-count value of 2 and net-salary total 5,500.75 for that company and payroll month. The user maps those source columns to output column labels, chooses Comma, and selects `FILENAME_CLIENT_PAYDAY`. A possible output name is `Payroll_101_2026-11-01.csv` if the source payroll-month date is 2026-11-01. The user can run it without a schedule or supply a schedule for future runs. [backend/app/payroll_source.py:27](/Users/apple/Desktop/ESC/backend/app/payroll_source.py:27), [backend/app/payroll_source.py:132](/Users/apple/Desktop/ESC/backend/app/payroll_source.py:132), [backend/app/retirement_results.py:168](/Users/apple/Desktop/ESC/backend/app/retirement_results.py:168), [backend/migrations/012_payroll_report_date_range.sql:9](/Users/apple/Desktop/ESC/backend/migrations/012_payroll_report_date_range.sql:9).

## What the user achieves

1. A reusable configuration with a database-generated job ID.
2. A manual-only job, or a job eligible for the background scheduler once its start date and time are saved.
3. A report whose detail rows follow saved filter and sort rules and whose output columns follow the mapping.
4. Optional database copies of generated output rows and optional recipient-specific email attachments.
